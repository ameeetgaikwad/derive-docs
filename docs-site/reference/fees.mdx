Two fee layers exist in the protocol. Only one is non-zero today.

## 1. Matching module fee — currently 0

Each fill can carry a module fee per side (`FillData.makerFee` / `takerFee`), **hard-capped on-chain by the `maxFee` each party signed** (`RFQM_FeeTooHigh`). The RFQ engine currently always submits **0** for both sides. A participant who signs `maxFee: 0` is cryptographically guaranteed zero module fee.

## 2. Open-interest (OI) fee

The StandardManager charges an OI fee inside the trade transaction whenever a trade **increases open interest** in an instrument (every newly written covered call does). It is charged **per side**, in cash (USDT), to the fee-recipient subaccount (id **3** on testnet):

```text
fee     = |amount| × forwardPrice(expiry) × OIFeeRateBPS    (18dp decimal math)
charged = max(fee, minOIFee)     per participant, only if subId OI increased
```

As deployed on chain 97: `OIFeeRateBPS = 0.001e18`, `minOIFee = 10e18` — i.e. **`max(0.1% of forward notional, 10 USDT)` per side**. Despite the parameter's "BPS" name it is a plain 18dp decimal multiplier.

<Note>
**History:** the original deploy shipped a `0.1e18` (10% of notional) placeholder — that is the 6,279 USDT-per-side fee visible on the [first live trade](/market-makers/worked-example). It was fixed on-chain on 2026-06-12 via the owner setter `SRMPortfolioViewer.setOIFeeRateBPS` (both the BTC OptionAsset and the BTCB base asset now read `0.001e18`), and the deploy-script default is fixed for future deployments.
</Note>

<Warning>
The rate remains **governance-settable** — **do not hard-code it.** Read the live values on-chain:

```text
SRMPortfolioViewer.OIFeeRateBPS(btcOptionAsset)   // viewer: 0xbC9ae813B45Fa950AabE2E82eAB023Dd45a36486
StandardManager.minOIFee()
```
</Warning>

Operational notes:

- The OI fee **is included** in the RFQ engine's off-chain maker-cash pre-check (estimated live from the same on-chain reads on every quote), and it is charged in the on-chain trade transaction — both sides must absorb it and still pass initial margin.
- Settlement and pure transfers that do not increase OI are not charged.

## Gas

- **Takers and makers pay no gas to trade** — fills are submitted by the protocol's executor.
- Participants pay gas only for their own setup, deposits, and withdrawals.
- On BSC testnet, all transactions must be legacy-typed at 0.2 gwei — see the [testnet guide](/resources/testnet#known-quirks).
